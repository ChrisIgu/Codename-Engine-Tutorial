# 🖼️SPRITES
ahora pasemos a el como añadir un fondo:

```
<sprite name="nombre" x="-600" y="600" scale="1.2" sprite="imagen" scroll="1" zoomfactor="0.55" updateHitbox="true" alpha="0.5" antialiasing="true" color="0xFF0000" flipX="true" flipY="true" angle="45" visible="false" blend="add"/>`
```

- **`name="nombre"`**: Es el nombre del objeto. Si luego quieres mover este sprite o cambiarle algo usando un script`.hx`, lo llamarás por este nombre.

- **`x="-600" y="600"`**: Es la **posición** en el juego.
    - `x` es horizontal (izquierda/derecha).
    - `y` es vertical (arriba/abajo).

- **`scale="1.2"`**: El **tamaño**. El valor `1` es el tamaño original. `1.2` significa que es un 20% más grande. Si pusieras `0.5`, se vería a la mitad.

- **`sprite="imagen"`**: Es el nombre de la imagen. El motor buscará un archivo llamado `imagen.png` dentro de la carpeta `folder="stages/pipisito/"` (No necesitas poner el `.png`).

- **`scroll="1"`**: Define el **Parallax** (el efecto de profundidad).
    - Si es `1`, se mueve a la par que la cámara.
    - Si es `0`, sigue a la cámara ( como si estuviera pegada a ella).
    - Si es `0.5`, se mueve más lento, dando sensación de que está muy lejos al fondo.

- **`zoomfactor="0.55"`**: Esto determina cuánto le afecta el **zoom de la cámara** del juego. Un valor bajo hará que el objeto no se haga tan grande cuando la cámara se acerque.

- **`updateHitbox="true"`**: En caso de que le cambies la escala a la imagen, esto le dice al motor que ajuste la hitbox al nuevo tamaño de la imagen para que el centro y las colisiones coincidan con el tamaño de la imagen. Si lo dejas en `false`, el objeto podría verse desplazado en caso de que le añadas colisiones.

- **`alpha="0.5"`**: Controla la **transparencia**. `1` es el objeto es visible, `0` es invisible.

- **`antialiasing="true"`**: Suaviza los bordes del sprite para que no se vea pixelado al escalarlo. Si tu mod es estilo pixel art, ponlo en `false`.

- **`color="0xFF0000"`**: Esto le aplica un filtro encima. En este ejemplo, el sprite se vería tintado de rojo, (funciona con códigos Hexadecimales).

- **`flipX="true"`** o **`flipY="true"`**: Voltea la imagen horizontal o verticalmente.

- **`angle="45"`**: Inclina el sprite. En este caso, estaría rotado 45 grados.

- **`visible="false"`**: El sprite existe pero no se ve. Útil si quieres que aparezca de repente mediante un **Script (.hx)** más tarde.

- **`blend="add"`**: Cambia el modo de mezcla. El modo `add` es genial para efectos de **luces, rayos o fuego**, porque hace que el sprite "brille" sobre el fondo. (Puedes ver la lista de blends aparte de add en [[5.5 Lista de blends]])

---

==No hace falta añadirlos todos al código del Sprite, ni en ese orden. añade solamente los que necesites para ese objeto, Por ejemplo.==

```
<sprite name="nombre" x="-600" y="600" sprite="imagen" flipX="true"/>
```

# 🎬 SPRITES ANIMADOS

Si tu Sprite no es solamente una imagen si no que lleva consigo un xml, debes usar el mismo código pero quitando el cierre del final ( `/>`: Cerrado || `>`: Abierto ), añadiendo el codigo de la animación y su nuevo cierre.

```
<sprite name="nombre" x="-600" y="600" sprite="imagen" type="beat" beatInterval="1" layer="back">
    <anim name="girar" anim="Venti Anim" fps="24" loop="true" indices="0,1,2,3"/>
</sprite>
```

---
#### **`type=""`**:
Este le dice al motor qué clase de objeto es:

- **`type="beat"`**: ¡Imprescindible! Hace que el sprite reaccione al ritmo de la música. Si lo usas, el sprite intentará reproducir su animación cada vez que haya un "beat".

- **`type="stick"`**: Hace que el sprite se "pegue" a la cámara o a otro objeto, ignorando ciertas reglas de movimiento del mundo. Su función principal es que, si el objeto "padre" se mueve, rota o cambia de tamaño, el objeto con `type="stick"` lo seguirá automáticamente como si estuviera atado con pegamento al `base=""`.

```
"El sprite que será la base"
<sprite name="mi_fondo" sprite="stage_back" x="0" y="0" />

"El sprite que se pega"
<sprite name="decoracion" sprite="fuego_efecto" type="stick" base="mi_fondo"/>
```

---
#### **`beatInterval=""`**
Si usaste `type="beat"`, este atributo controla cada cuántos beats ocurre la acción.

- **`beatInterval="1"`**: El objeto se mueve o anima en cada pulso (1, 2, 3, 4...).
- **`beatInterval="2"`**: Lo hace cada dos pulsos (1, 3, 5, 7).
- **`beatInterval="4"`**: Solo una vez por cada compás (measure).

---
#### **`layer=""`**

Aunque el orden en el archivo XML define quién va delante o atrás de quien, con `layer=""` puedes forzarlo:

- **`layer="back"`**: Se va al fondo del todo.
- **`layer="front"`**: Se pone delante de todo (incluso de los personajes, a veces).
- **`layer="icons"`**: Se dibuja en la misma capa que los iconos de vida.
- **`layer="top"`**: Lo coloca por encima de absolutamente todo, incluyendo las flechas (strums).

Además de `layer`, existe el atributo **`z="10"`**.

- Si dos sprites están en la misma capa (ej. ambos en `back`), el que tenga el número `z` más alto se verá por encima del otro.

---
- **`anim name=""`**: Apodo que quieras ponerle al sprite.

- **`anim=""`**: Nombre de la animación en el xml de tu sprite.

- **`fps=""`**: Son los frames por segundo a los que corre la animacion.

- **`loop="true"`**: tenerlo en true repite la animación sin parar, si deseas que solo se reproduzca la animación cuando lo llames en tu Script`.hx` ponlo en false.

- **`indices="0,1,2,3,4,5"`**: Dentro de la etiqueta `<anim>`, esto le dice al motor que ignore el resto y solo use esos fotogramas específicos.

---

con `<high-memory>` puedes definir que objetos aparecerán solo en caso de que el jugador haya desactivado la opción de low quality ( Se usa para mejorar el rendimiento ). Por ejemplo:

```
<high-memory>

<sprite name="nombre" x="-600" y="600" sprite="imagen" type="beat" beatInterval="1" layer="back">
    <anim name="girar" anim="Venti Anim" fps="24" loop="true" indices="0,1,2,3"/>
</sprite>

</high-memory>
```

# **⚖️ La importancia de la jerarquía (El Orden)

los XML's se leen de **arriba hacia abajo**, ¿Qué quiere decir?.

- Lo que escribas primero quedará al **fondo** del escenario.
- Lo que escribas después se dibujará **encima**.
- **Dato importante:** Si pones un `<sprite>` después de `<boyfriend>`, el sprite tapará al personaje a menos que uses `layer="back"`.

# **🎥HUD**

En caso de que quieras hacer un HUD personalizado en XML este esta muy limitado para ello, ¿Qué es lo que puedes y no puedes hacer?.

Puedes "forzar" objetos al HUD usando el atributo **`layer="icons"`** o **`layer="top"`**.

Si quieres que un sprite (un marco de televisión, una marca de agua o un filtro) esté siempre por encima de las flechas y la barra de vida, añádelo de esta forma a tu XML:

```
<sprite name="mi_filtro" sprite="vignette" layer="icons" scroll="0" zoomfactor="0" />
```

- **`layer="icons"`**: Lo coloca en la misma capa que la barra de vida y los iconos.
- **`layer="top"`**: Lo coloca por encima de absolutamente todo**, incluyendo las flechas (strums).
- **`scroll="0"`**: Esto hace que el objeto no se mueva cuando la cámara se mueva. Se queda pegado a la pantalla.
- **`zoomfactor="0"`**: Evita que el objeto se haga grande o pequeño cuando la cámara hace zoom.

Aunque puedes poner imágenes estáticas o animadas en el HUD desde el XML, hay cosas que **solo puedes hacer con un script `.hx`**:

- **Interactividad Real:** Si quieres que un objeto del HUD cambie cuando tu vida esté baja (ej. que el marco se ponga rojo), necesitarás Haxe.
-  **Posicionamiento Dinámico:** Si quieres que algo se mueva siguiendo a la barra de vida exactamente, necesitarás Haxe.
-  **Elementos del Sistema:** Cosas como textos que cambian (puntuación, precisión) o barras de progreso personalizadas requieren código Haxe.
